# ENGRAM development

ENGRAM is a local desktop application with a Tauri 2 native shell, a React/TypeScript renderer and a shared Rust analysis core for the user's explicitly selected offline data. The Atlas Focus interface uses the user-selected jagged cobalt-blue lightning creature, graphite surfaces and cobalt controls. Use "Trace desk", "Trace map" and the slogan "Find what remains." Present the working application and its real workflows directly. Use the release name and application version in product labels. Keep demo labels, reader states, experimental coverage and unavailable functionality accurate. Version 0.6.0 continues the Tauri application and schema-1 cases with an optional, bounded review map, and adds separate Markdown/CSV report artifacts. Release evidence must identify the matching source revision, native captures and platform archives. Earlier release artifacts retain their original appearance and provenance; do not relabel them as current screenshots or binaries. Design illustrations under `assets/design/` remain distinct from actual native captures under `assets/screenshots/`.

Never scan the user's personal directories during development. Exercise the engine with generated synthetic fixtures. Never commit real backups, credentials, personal messages or machine paths. Never validate discovered credentials against a service. Never write to source evidence, follow symlinks, bypass OS protections, or claim that an unlinked file proves permanent deletion.

`crates/engram-core/src/model.rs` is the shared interface. Coordinate interface changes before changing it. The core owns parsing and evidence; desktop and CLI use the same core. Keep source reads bounded, report partial coverage and skip reasons, and mask secrets before they enter any persistent case or event.

Finding bookmarks, review states and notes are analyst metadata, separate from source evidence and engine confidence. Persist them only through the validated native save-case snapshot, against known finding IDs. Preserve the sparse optional schema-1 review representation, annotation/note limits, stable dirty-state identity and cancelled-save behavior. Baseline review metadata stays read-only. Never treat annotation edits as evidence changes or silently discard an unsaved review during source replacement or close.

Report export uses the same guarded Rust-held snapshot and shared core renderer. Accept only selected known IDs and bounded options over IPC; never accept an arbitrary renderer filepath, evidence object or file content. Exporting a report does not accept a review as saved or mutate source evidence. Keep notes, full structured paths and detail fields opt-in, escape Markdown, neutralize CSV formula prefixes and enforce output/selection limits without truncation. Field minimization is not universal anonymization: optional notes and source text can remain private. Reports are not restorable cases.

The renderer lives in `apps/desktop`, and native commands in `apps/desktop/src-tauri`. Keep filesystem selection and case persistence in Rust. Do not add unrestricted filesystem, shell, remote content or arbitrary path IPC to make a UI control work. Source paths stored inside imported cases remain inert metadata.

Register each native command in the invoke handler, the build manifest and the narrowly scoped local capability. Verify the actual renderer-to-native call; a passing backend unit test does not establish that the command is callable from the packaged interface.

Version 0.7 adds the media gallery and guided iPhone backup inspection. Source preview authority is a transient MediaAccess created by an actual scan, never reconstructed from imported Case paths. Preview requests contain only known case/finding IDs; revalidate captured paths and SHA-256 before returning bounded, newly encoded PNG pixels. Clear images and pending requests on every observation replacement, even if an imported case reuses an ID. Keep previews out of saved cases, logs and reports. Backup selection tokens are native-owned, one-use handles to explicit picker selections; recheck compatibility before scanning. Preflight counts describe indexed paths rather than verified findings. Keep preview, metadata and scan errors visible without losing the existing case or review.

Run formatting, core/CLI and native backend tests, clippy, frontend type checking/Vitest, and the production frontend/native builds. Build the frontend before a standalone Cargo desktop check or use the Tauri CLI. Standalone embedded desktop builds need `engram-desktop/custom-protocol`. Verify an actual Tauri window and IPC; browser fixture screenshots are additional UI QA and must never be labelled native captures. The browser fixture must come from the real Rust CLI synthetic demo, not invented result counts. Documentation must describe final observed behavior.

Both lockfiles are part of the reproducible build. A bootstrap CI run may upload a resolved Cargo.lock during migration; commit it and require a subsequent successful locked-source check before calling the release verified. Never bypass an operating-system application-control block to run a local compiler.
