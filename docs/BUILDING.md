# Build ENGRAM

ENGRAM uses a Tauri 2 native shell and a React/TypeScript frontend. Version 0.6.0 adds report export to the Atlas Focus review workspace. The Rust engine and CLI share the workspace. Earlier releases retain their own source and provenance; the 0.1 release used egui, so its binaries and capture flags are not the current desktop build.

Install the current stable Rust toolchain compatible with the workspace's declared minimum and dependency requirements using the [official Rust installer](https://www.rust-lang.org/tools/install). SQLite is built through the bundled crate feature, so a platform C compiler is required.

Install Node.js 24 and the platform dependencies in the [official Tauri prerequisites](https://v2.tauri.app/start/prerequisites/). Use the committed `Cargo.lock` and `apps/desktop/package-lock.json`.

## Start the native desktop

From the repository root:

```bash
cd apps/desktop
npm ci
npm run tauri -- dev -- -- --demo
```

The Tauri CLI starts the local Vite development server and the Rust application together. The second `--` separates application arguments from Cargo runner arguments. The default view is the synthetic demonstration; real sources require native selection.

`npm run dev` alone is a **browser-only synthetic demonstration**. It exercises the React layout, review controls, search, map navigation and report options with a checked-in case generated by the Rust CLI, but has no native source/case/report dialog bridge. Reviews stay in the current tab and are not persisted automatically. A successful browser demonstration does not prove a native Tauri build or report write.

## Windows

Use Rust's MSVC toolchain and the Microsoft C++ Build Tools with the Windows SDK. The desktop also requires Microsoft Edge WebView2 Runtime. The portable archive does not install WebView2 itself. CI uses the standard Windows runner toolchain.

```powershell
cd apps/desktop
npm ci
npm run tauri -- build --no-bundle --ci -- --locked
cd ../..
cargo build -p engram-cli --release --locked
.\target\release\engram-desktop.exe --demo
```

The production frontend is embedded through Tauri's custom protocol. Development needs Node.js; a packaged app uses the installed WebView2 runtime and does not require a Vite server.

## macOS

Install Rust, Node.js and the Xcode Command Line Tools. Build on the intended architecture; the artifact workflow uses the architecture of the selected GitHub runner. The CI and artifact workflows select `macos-15` for the Apple Silicon build.

```bash
xcode-select --install
cd apps/desktop
npm ci
npm run tauri -- build --bundles app --ci -- --locked
```

The application bundle is written under the workspace's `target/release/bundle/macos/ENGRAM.app`. Current distribution packages are unsigned and not notarized. Packaging a `.app` is distinct from proving that distribution signing and notarization are complete.

## Linux

An example Ubuntu/Debian dependency set for native desktop building:

```bash
sudo apt-get update
sudo apt-get install -y build-essential pkg-config libwebkit2gtk-4.1-dev \
  libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
cd apps/desktop
npm ci
npm run tauri -- build --no-bundle --ci -- --locked
cd ../..
./target/release/engram-desktop --demo
```

A graphical session, GTK 3 and WebKitGTK 4.1 runtime libraries are needed to run the Linux binary. This tar archive is not an AppImage and does not bundle the system WebKit runtime. Core and CLI tests do not require a display server.

## Development checks

```bash
cargo fmt --all -- --check
cargo test -p engram-core -p engram-cli --locked
cd apps/desktop
npm ci
npm run format:check
npm run typecheck
npm test
npm run build
cd ../..
cargo test -p engram-desktop --features engram-desktop/custom-protocol --locked
cargo clippy --workspace --all-targets --features engram-desktop/custom-protocol --locked -- -D warnings
```

Tests generate synthetic sources in temporary directories. Frontend tests cover review validation and identity, structured search, filtering, map layout and viewport bounds. Rust tests cover optional review serialization, bounded imports and save-session validation in addition to existing reader and source-preservation behavior. A test being present is distinct from its execution passing: record native results from the corresponding completed CI run. Do not point development scripts at personal backups. Review [methodology](METHODOLOGY.md) when adding or testing a reader.

The [0.6.0 verification run](https://github.com/Forem0/ENGRAM/actions/runs/40874129225) records frontend validation and production assets, plus Rust formatting, core/CLI/native backend tests and Clippy on Windows, macOS and Linux. It also records actual native startup and report interaction on Linux. Report regressions cover selected IDs, minimal-field defaults, markup and formula handling, deterministic output, limits, safe destinations and non-mutating export snapshots. Operating-system protections remain in force; use an authorized build environment when a local compiler is blocked.

Build the production frontend before a standalone Cargo desktop command. Unlike the Tauri CLI, plain Cargo does not run `beforeBuildCommand`. The `engram-desktop/custom-protocol` feature embeds `apps/desktop/dist`; it prevents a standalone release/smoke build from depending on the development URL.

## Native smoke verification and screenshots

The Linux CI smoke job runs the actual Tauri executable under Xvfb and a D-Bus session, with WebKit's software rendering fallback. The renderer loads the real Rust-generated synthetic case, selects the requested view, and calls the guarded `finish_smoke_test` command. The backend verifies an active synthetic case and prints `ENGRAM_TAURI_SMOKE_OK` only for an explicit `--smoke-test` launch.

CI then captures the visible native window with ImageMagick before the delayed process exit. The artifact contains PNG captures, per-view IPC logs and a freshly generated `demo-case.json`. This evidence is separate from browser/Playwright fixture captures.

The six 0.6.0 Atlas Focus views and two report screens in the README come from the [successful native Tauri/IPC job](https://github.com/Forem0/ENGRAM/actions/runs/40874129225/job/123451027724), using the actual [PR merge checkout 9c7d9c3](https://github.com/Forem0/ENGRAM/commit/9c7d9c3e1e65b9ce95d597b3f59dc41a885afeaa). The [verification run](https://github.com/Forem0/ENGRAM/actions/runs/40874129225) records all seven passing checks. All six startup launches report `ENGRAM_TAURI_SMOKE_OK`; the separate report interaction reports `ENGRAM_NATIVE_REPORT_PICKER_OK`. The eight unedited images are 1440 × 940 pixels and use a synthetic case. [Capture provenance](../assets/screenshots/README.md) records the exact checkout/tree, artifact identity, image hashes and execution evidence.

The Atlas Focus illustrations under `assets/design/atlas-focus/` record the selected visual direction. They are not native captures and must not be used to establish that a build or command bridge ran. The PNGs under `assets/screenshots/` carry their own release/source provenance.

No WebKit sandbox-disabling option is set. A native smoke failure must remain a failure; do not replace its screenshot with a browser image or an earlier egui capture.

## Native report interaction

The Linux CI job additionally runs [`scripts/native-report-smoke.sh`](../scripts/native-report-smoke.sh) in an isolated Xvfb display and D-Bus session. This is a separate ordinary `--demo` launch, without the startup smoke process's timed exit. The script drives the visible Tauri window with normal mouse and keyboard events. The `rfd` destination dialog uses the real XDG FileChooser portal and GTK backend; no picker mock, renderer JavaScript injection or arbitrary-path command is added to the application.

The exercise saves a real engine-generated synthetic case through the native **Save case** dialog, opens **Export report**, cancels an actual report picker, then writes new Markdown and CSV reports through the normal native command. Each result is compared byte for byte with `engram export` rendering that exact saved snapshot. Independent parsing checks CSV finding IDs and order, UTF-8 BOM and CRLF records, version metadata, filename-only paths and the omission of optional source details and analyst notes. Hash and byte counts are checked against the shared-engine CLI receipts; the native receipt screens were visually inspected and match the recorded report hashes, rather than being machine-parsed.

The artifact's `report-smoke/` directory contains picker, configuration and receipt screenshots, interaction logs, the saved synthetic snapshot, report outputs, CLI receipts and `verification.json`. The saved input case is checked for unchanged bytes. A successful exercise emits `ENGRAM_NATIVE_REPORT_PICKER_OK` only after these checks complete.

This proves the exercised Linux/X11/WebKitGTK path. It does not exercise unsaved annotation edits, overwrite-picker confirmation, Windows/macOS GUI interaction or real user evidence. Rust snapshot/output regressions cover invalid and stale requests, review retention and existing-output rejection. Browser fixture tests remain additional UI evidence. The six startup captures establish initial native rendering and IPC separately from this report exercise.

After building the debug desktop and CLI, the Linux interaction can be run with the same display dependencies plus `xdg-desktop-portal` and `xdg-desktop-portal-gtk`:

```bash
timeout 180s xvfb-run -a -s '-screen 0 1600x1100x24' \
  dbus-run-session -- env ENGRAM_EXPORT_X=1035 ENGRAM_EXPORT_Y=35 \
  bash scripts/native-report-smoke.sh native-captures/report-smoke
```

Use a new output directory for each run. The coordinates identify **Export report** in the verified 1440 × 940 workspace; review them if the layout changes. Run this script only against synthetic fixtures in an isolated display.

## Lockfile bootstrap during migration

The CI prepare job checks the committed Rust lockfile. If the Tauri migration requires a new resolution, it uploads a single shared `dependency-lockfile` artifact for all platform jobs. Those jobs use the resolved file with `--locked`, but the final committed-lockfile gate deliberately fails until that file is committed and verified again. An optional manual `refresh_lockfile` input also enters this explicit bootstrap state.

## Build artifacts

The manually dispatched [Build artifacts workflow](../.github/workflows/build-artifacts.yml) requires the committed lockfile, tests the frontend/backend, builds through the Tauri CLI and uploads platform archives with SHA-256 checksums. Windows gets a portable ZIP; Linux gets a binary tar archive with runtime prerequisites; macOS gets a tar archive containing the proper `.app` bundle. Each includes the CLI and documentation.

The [Build artifacts workflow](https://github.com/Forem0/ENGRAM/actions/workflows/build-artifacts.yml) records platform packaging jobs. The [0.6.0 release](https://github.com/Forem0/ENGRAM/releases/tag/v0.6.0) accompanies published archives with their checksums and exact build provenance. The [0.5.0 release](https://github.com/Forem0/ENGRAM/releases/tag/v0.5.0) and [0.4.0 release](https://github.com/Forem0/ENGRAM/releases/tag/v0.4.0) retain their own source, interface and verification evidence.

The workflow does not publish a release or install signing credentials. A successful compile is not a substitute for exercising the packaged executable on its target platform. Release availability, provenance and download links are updated only after build artifacts are actually verified and published.
